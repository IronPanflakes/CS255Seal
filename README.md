# CS255Seal
The DriverPass project involved designing a system for a small driving‑instruction company that wanted an online platform for students to register, schedule lessons, take practice tests, and track their progress. I did particularly well in translating the client’s interview responses into clear business requirements and then building a system design that directly supported those needs. If I were to revise one part, I would refine the activity and sequence diagrams to make the process flows even clearer and more consistent. I interpreted the user’s needs by focusing on what the client emphasized—convenience, scheduling flexibility, and accessible learning tools—and ensured those priorities shaped the system’s features and structure. Considering user needs is essential because a system only succeeds if it solves the right problems in a way that feels intuitive to the people using it. My approach to software design centers on gathering requirements, modeling workflows, and validating assumptions early, and in the future I would continue using techniques like UML diagrams, user stories, and iterative refinement to analyze and design effective systems.
